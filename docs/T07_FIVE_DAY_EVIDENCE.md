# 과제7 실제 5일 기록 및 동일 지표 비교 체크리스트

> 이 문서는 기록 방법과 계산 규칙을 정의한 안내서다. **실제로 작성하지 않은 날짜·실행 시간·수정 사유·통과 결과는 넣지 않는다.**

## 고정 질문
**“선택한 계획에서 오늘 실제 실행한 작업 시간은 총 몇 분인가?”**

- 지표: 실제 수행 시간 (`actual_minutes`), 단위: **분(min)**.
- 근거: 로그인한 본인 계정의 `execution_logs` ↔ `tasks` ↔ `plans` 관계. `Do` 입력에서 기록된 데이터만 사용.
- 날짜: 실행 기록 `started_at`을 **Asia/Seoul(KST)**로 변환한 날에 귀속한다.
- 범위: 비교하는 다섯 날짜 내 **동일한 계획 ID**만 포함. `deleted_at`이 있는 할 일은 과제6 See 규칙과 같이 제외.
- 합계: 그날 적합한 기록의 `actual_minutes`를 정수로 더한다. 일 단위 정수 합계는 반올림하지 않는다.
- 누락값: 기록이 없는 날은 `0분`이 아니라 **기록 없음(NA)**로 표기한다. 실제 0분을 기록한 행이 있어야 `0분`으로 인정한다.
- 중복값: `task_id + started_at + ended_at + actual_minutes + blocked_reason`가 정확히 같은 행은 중복 후보로 표시하고 첫 행 한 개만 집계한다. 원본 DB 행은 삭제하지 않는다.
- 이상값: 한 번의 실행에 `actual_minutes > 480`분이면 검토 대상으로 표시하되 자동 삭제/보정하지 않는다.
- 반올림: 하루의 합계는 분 정수. 전/후 평균은 소수점 첫째 자리까지 반올림한다.
- 주 시작 요일: **월요일**, 날짜·시간 기준은 모두 KST.

## 실제 5일 기록 표 (빈칸은 사용자가 실제로 채우기)

| 순서 | 실제 기록한 날짜(KST) | 실행 기록 근거 ID | 그날의 합계(분) | 메모 |
|---|---|---|---|---|
| 1일차 | 미작성 | 미작성 | 미측정 | 규칙 변경 전 |
| 2일차 | 미작성 | 미작성 | 미측정 | 규칙 변경 전 |
| 3일차 | 미작성 | 미작성 | 미측정 | 규칙 변경 후 |
| 4일차 | 미작성 | 미작성 | 미측정 | 규칙 변경 후 |
| 5일차 | 미작성 | 미작성 | 미측정 | 규칙 변경 후 |

이 표는 **실제 다섯 개의 서로 다른 날짜**와 원본 근거가 채워져야 완성된다. 기록을 뒤늦게 만들거나 시간을 소급해서 만들어 기재하지 않는다.

## 변경 규칙은 단 한 번

- **2일차와 3일차 사이**에 동일한 계획을 한 번 수정한다.
- 실행 규칙을 구체적으로 한 가지 바꾼다. *예시: 집중 작업 세션 목표를 60분에서 30분으로 변경*. 이 문구는 예시이며 실제 적용 여부를 확인해야 한다.
- 수정 시각·변경 전후 값은 `plan_revisions` / 계획의 수정 이력 화면에서 확인한다.
- 변경 이유는 당시의 실제 이유를 기록한다. 예: 2일차의 집중 유지 문제(실제로 그런 문제가 있었다면). 증거가 없는 이유를 만들지 않는다.
- **지표는 변경 전후 모두 같은 “일별 실제 수행 분”**으로 유지한다.

## 비교 계산 (실제 기록 후만 입력)

- 변경 전 평균 = (1일차 분 + 2일차 분) ÷ 2.
- 변경 후 평균 = (3일차 분 + 4일차 분 + 5일차 분) ÷ 3.
- 전/후 차이(분/일) = 변경 후 평균 − 변경 전 평균.
- 변화율(%) = (전/후 차이 ÷ 변경 전 평균) × 100. 단, 변경 전 평균이 0이면 백분율 대신 `정의 불가`라고 표시.
- **수동 검산**: 실제 분 합계와 평균을 계산식과 함께 보고서에 적고, 프로그램 결과와 대조한다.
- 누락값이 하나라도 있으면 다섯 날짜 모두 기록 완료라고 하지 않는다. 완료 기록 5일을 확보한 다음 비교한다.
- 비교 변화가 있다는 사실만으로 규칙 변경이 그 결과의 원인이라고 단정하지 않는다.

## 원본 근거 및 보안 확인

1. 실제 계정으로 과제7에 로그인하고 하나의 계획에서 `Do` 기록을 적립한다.
2. 계획 화면의 **수정 이력**과 `See` 집계·근거 기록을 확인한다.
3. **내 자료 내보내기**에서 본인 계정의 JSON을 저장한다.
4. JSON의 `plans`, `tasks`, `execution_logs`, `plan_revisions`로 다섯 날짜와 변경 전후 내용을 교차 확인한다.
5. 제출 스크린샷에는 비밀번호, 세션 쿠키, DB 연결 문자열, 다른 계정 정보가 노출되지 않도록 한다.

### 아직 결정되지 않은 사실
기준이 될 **실제 계획 ID, 측정한 다섯 날짜, 규칙 변경 시각/이유, 실제 수치**는 아직 확인되지 않았다. 해당 부분은 실제 사용 후에만 채운다.
