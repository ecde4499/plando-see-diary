## 5. 남은 필수 검증

1. **회원가입 완료 과정**: 별도 테스트 계정으로 실제 등록 요청(201), 세션 쿠키, 재로그인, 중복 계정/오류 표시 확인.
2. **실서비스 API 계정 격리**: 신규 별도 테스트 계정 또는 기존 테스트 계정으로 상호 소유한 계획/작업 ID에 대한 요청이 404/401인지, JSON 내보내기가 본인 소유로 한정되는지 확인. 불필요한 운영 데이터 변경을 피하고 세션/비밀번호를 외부에 노출하지 않는다.
3. **GitHub Actions 최신 CI 결과**: `unit-and-http-smoke`, `isolated-postgres-http` 두 작업의 결과 URL/일시를 확인하여 PASS 근거를 남긴다.
4. **의존성 점검**: Render의 `npm ci` 빌드 로그에 `2 vulnerabilities (1 moderate, 1 high)`가 있어, `npm audit`로 항목별 확인 후 테스트를 통과하는 패치 계획이 필요하다. 취약점 원인·영향은 미분석이다.
5. **실제 5일 기록 및 규칙 1회 변경**: 같은 계획에서 서로 다른 실제 5일의 수행 시간과 2일/3일차 사이 한 번의 규칙 변경, 전후 비교를 직접 남겨야 한다. 미실시 날짜/분을 가짜로 작성하지 않는다. 절차는 [T07_FIVE_DAY_EVIDENCE.md](T07_FIVE_DAY_EVIDENCE.md).
4. **제출 증거**: 실제 화면 스크린샷, 세션/민감정보가 제외된 API 테스트 결과, CI 실행 URL, 5일 실행·변경 근거를 제출 요구사항에 맞춰 준비한다.
